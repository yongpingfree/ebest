# Beansmile 团队需求说明：OMS / WMS / eBest App 变更

## 1. 背景与范围

本文档说明为配合供应商上架系统及接口安全加固，需要 beansmile 团队在 OMS、WMS 及 eBest App（iOS / Android）中完成的变更。

涉及接口：`app/api/v1/items`（商品接口）及新增的供应商发货查询接口。

优先级：以下四项均为第一优先级。

| 编号 | 需求 | 涉及系统 |
|------|------|----------|
| 1 | 商品接口增加按供应商、SKU 查询库存与销量 | OMS |
| 2 | 商品接口安全加固（Authorization 令牌） | OMS、iOS App、Android App |
| 3 | 新增供应商发货查询接口 | OMS（必要时 WMS） |
| 4 | OMS 导出数据权限拆分 | OMS |

---

## 2. 需求一：商品接口增加库存与销量查询（只读）

### 2.1 现状
`app/api/v1/items` 当前一次返回全部在售商品，不支持按供应商或 SKU 过滤。

### 2.2 需求
在该接口中增加只读的库存与销量查询能力，支持按供应商、SKU 或两者组合查询。

### 2.3 查询规则

| 输入 | 返回结果 |
|------|----------|
| 同时提供供应商和 SKU | 返回该供应商名下、且 SKU 匹配的商品 |
| 仅提供供应商 | 返回该供应商名下的商品 |
| 仅提供 SKU | 返回 SKU 匹配的商品 |
| 两者都不提供 | 保持现有行为，返回当前全部商品 |

### 2.4 返回内容
- 商品基本信息（SKU、名称、供应商）。
- 当前库存数量。
- 销量数据（统计周期由 beansmile 与 eBest 确认）。

### 2.5 约束
- 接口为只读，不得修改任何库存或订单数据。
- 不影响现有 App 对该接口的调用方式和返回结构。
- 该接口同样受需求二的令牌校验约束。

---

## 3. 需求二：商品接口安全加固

### 3.1 目标
防止未授权方直接调用 `app/api/v1/items` 抓取商品数据，同时保证已发布的旧版 App 在过渡期内仍可正常使用。

### 3.2 Authorization 令牌

- 接口增加可配置的 Authorization 令牌。
- 客户端提供有效令牌时，接口才返回数据。
- 令牌值放在 OMS 配置中，可由 eBest 修改，不写死在代码中。

### 3.3 令牌版本管理与 App 同步发布

- OMS 与 iOS / Android App 之间建立令牌版本机制。
- 携带有效令牌版本的 App 新版本，需与 OMS 的对应变更在同一时间窗口发布。
- OMS 需能同时识别当前有效的令牌版本，避免发布期间出现部分客户端被拒绝的情况。

### 3.4 过渡期兼容

过渡期内并非所有客户都已升级 App。过渡期规则如下：

- 当请求缺少令牌或令牌错误时，如果请求来自正版 eBest App，接口仍然返回数据。
- 正版 eBest App 的判定条件：请求头同时包含以下字段，且取值有效：
  - `app-os-version`
  - `current-app-version`
  - `current-store-id`
  - `current-postal-code`
  - `current-suburb`
  - `current-delivery-area-id`
  - `local`
- 不满足上述条件且令牌无效的请求，一律拒绝。

### 3.5 过渡期开关

- 增加一个配置开关，用于关闭上述过渡期兼容。
- 开关由 eBest 在后续时间自行配置，例如全部客户升级到最新版 App 之后。
- 开关关闭过渡期后，只有携带有效令牌的请求才能获得数据。

### 3.6 验收要点

| 场景 | 预期 |
|------|------|
| 带有效令牌 | 返回数据 |
| 无令牌或令牌错误，请求头符合正版 App 特征，过渡期开启 | 返回数据 |
| 无令牌或令牌错误，请求头不完整，过渡期开启 | 拒绝 |
| 无令牌或令牌错误，请求头符合正版 App 特征，过渡期已关闭 | 拒绝 |
| 带有效令牌，过渡期已关闭 | 返回数据 |

## 4. 需求三：供应商发货查询新接口

### 4.1 输入

| 参数 | 说明 |
|------|------|
| 供应商名称 | 供应商在系统中登记的名称 |
| 日期 | 格式 yyyymmdd |

### 4.2 输出

输出分为三部分，其中前两部分仅当输入日期为当天时返回。

**（一）待发货订单明细（仅当天）**
- 需要发货的订单列表及订单明细。
- 每个订单包含预计送达日期。

**（二）缺货商品清单（仅当天）**
- 列出缺货商品及其 SKU。
- 缺货的定义包括两种情况：
  - 当前库存数量为 0。
  - 当所有待发货订单全部发出后，库存数量将变为 0。

**（三）退货及反馈记录**
- 范围：从输入日期起往前 10 天，包含输入日期当天。
- 内容：
  - 客户退回的商品。
  - 客户留下的备注或投诉。
  - eBest 运营团队留下的备注。

### 4.3 约束
- 只读接口，不修改任何数据。
- 供应商只能查询自己名下的数据，需要认证。
- 输入日期不是当天时，（一）、（二）两部分返回为空，仅返回（三）。

## 5. 需求四：OMS 导出数据权限拆分

### 5.1 现状
OMS 中商品和订单页面各有一个“导出数据”按钮，目前没有独立的权限控制。

### 5.2 需求
新增两项权限：

| 权限 | 控制范围 |
|------|----------|
| `product_export` | 商品页面的“导出数据”按钮及导出功能 |
| `order_export` | 订单页面的“导出数据”按钮及导出功能 |

### 5.3 规则
- 只有拥有 `product_export` 的用户才能导出商品数据。
- 只有拥有 `order_export` 的用户才能导出订单数据。
- 没有对应权限的用户，不显示导出按钮；同时服务端也必须校验权限，不能仅隐藏按钮。
- 权限可在 OMS 角色或用户权限管理中分配。
- 上线时，需要由 eBest 为现有需要导出的用户补充分配权限，避免影响日常工作。

## 6. 各系统变更汇总

| 系统 | 变更内容 |
|------|----------|
| OMS | 需求一的查询过滤；需求二的令牌校验、令牌版本、过渡期判定及开关；需求三的新接口；需求四的两项新权限及服务端校验 |
| WMS | 需求三中如发货、库存数据由 WMS 持有，需提供数据来源或同步方式，由 beansmile 评估确认 |
| iOS App | 请求 `app/api/v1/items` 时携带 Authorization 令牌，并实现令牌版本管理 |
| Android App | 同 iOS App |

---

## 7. 发布与上线要求

- OMS 与 iOS / Android App 的令牌相关变更需在同一时间窗口发布。
- 上线顺序建议：先发布 OMS（过渡期开关保持开启），再发布 App，待绝大多数客户升级后，由 eBest 关闭过渡期开关。
- 每次升级后需执行的常规操作由 beansmile 在发布说明中列明。
